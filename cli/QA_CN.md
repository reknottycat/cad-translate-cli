# cli-anything-cad 问题报告

## 范围

本文档总结截至 2026-03-16，当前本地 CAD CLI 线束中已经确认的问
题、风险点和运行限制。

## 重构说明（2026-03-25）

当前 CAD CLI 正在按 CLI-Anything 的 harness 标准重构。旧实现已归档到
`agent-harness/cad-translate_legacy/`，并且被刻意排除在运行时、打包和
pytest 扫描范围之外。

CLI-Anything 作为开发参考的技能包保留，不是运行时依赖。

本问题报告依然可以作为“问题清单”使用，但在先收敛骨架、再逐步回填 CAD
专项能力的过程中，部分问题的优先级可能会发生变化。

## 高优先级问题

### 1. HaoChen COM 可能被探测到，但保存阶段仍可能失败

- 现象：
  后端探测可能会把 `haochen_com` 标记为已检测到，但如果本机浩辰 CAD
  虽已安装、却没有可用授权，实际转换或保存时仍可能失败。
- 影响：
  自动后端选择仍可能先尝试 HaoChen，导致一次失败后再进入回退链。
- 当前缓解方式：
  已有后端探测和自动回退，且可通过禁用后端减少影响。
- 建议下一步：
  增加更强的“可保存能力探测”，对失败的后端自动降级。

### 2. OpenRouter 免费模型仍可能被上游限流

- 现象：
  即使配置和连接都正确，真实翻译请求仍可能返回 `429`。
- 影响：
  大批量翻译时可能出现重试、回退或延迟增大。
- 当前缓解方式：
  已支持主模型和备用模型健康探测，也支持 NVIDIA 直连作为备用路径。
- 建议下一步：
  增加按 provider 区分的重试策略，并提供更直观的健康状态摘要。

### 3. 项目级配置已经能读取，但写入仍偏向全局配置

- 现象：
  当前系统已经支持读取 `.cli-anything-cadrc`，但 `config set`
  默认仍写入全局主配置文件。
- 影响：
  用户可以读取项目级覆盖，但还不能很方便地通过 CLI 写入项目级配置。
- 当前缓解方式：
  用户可以手动维护项目配置文件。
- 建议下一步：
  为 `config set/unset` 增加 `--scope project|global`。

## 中优先级问题

### 4. DWG 后端能力还没有以能力矩阵方式呈现

- 现象：
  当前用户还看不到“哪个后端更适合保图像、哪个更快、哪个更稳定”的清晰总结。
- 影响：
  排障时仍需要靠文档和试错。
- 当前缓解方式：
  `config show` 已经能显示探测到的后端和禁用状态。
- 建议下一步：
  增加 `doctor` 或 `backends inspect` 命令，显示能力说明。

### 5. 大 Excel 翻译批处理仍比 CAD 本地步骤更慢、更不稳定

- 现象：
  提取和回写是本地稳定流程，但在线翻译速度仍取决于模型和 provider。
- 影响：
  用户可能误以为整个流程卡死，实际上慢的是 LLM 阶段。
- 当前缓解方式：
  已支持 glossary、prompt 模式和模型回退。
- 建议下一步：
  增加批次进度、日志和可恢复输出。

### 6. 配置编辑仍偏命令行化

- 现象：
  当前已有 `config show/get/set/validate`，但还没有 `config unset`
  和 `config edit/open`。
- 影响：
  删除配置和快速修正嵌套项还不够方便。
- 建议下一步：
  增加 `config unset` 和 `config open`。

## 低优先级问题

### 7. 文档分布在多个 Markdown 文件中

- 现象：
  当前说明分布在 `README.md`、`TEST.md`、`QA.md` 等多份文档里。
- 影响：
  结构已经可用，但仍有一定重复信息。
- 建议下一步：
  增加更短的总索引页或命令速查表。

### 8. 依赖和旧 schema 的 warning 债务仍然存在

- 现象：
  测试输出中仍有 Pydantic、SQLAlchemy、openpyxl 的弃用 warning。
- 影响：
  目前不阻塞使用，但会增加输出噪音，掩盖真正的回归问题。
- 建议下一步：
  单独做一轮依赖清理。

## 当前整体判断

- CAD 本地工作流：
  可用
- DXF 提取与回写：
  稳定
- DWG 自动转换：
  可用，但不同后端能力差异明显
- LLM 配置能力：
  较强
- LLM 批量翻译稳定性：
  可接受，但仍受 provider 影响
- 配置架构：
  已经比较健康，下一步重点是补项目级写入和诊断命令
